### 1.2 Architecture

- **Pattern**: Clean Architecture (4 camadas — backend) + Feature-Sliced Design refinado (frontend)
- **Backend Layers**: `domain/` → `application/` → `infrastructure/` + `shared/`
  - Dependency rule: all arrows point inward, domain has zero external dependencies
- **Frontend Layers**: `app/` → `pages/` → `features/` → `shared/`
  - React Router for SPA navigation, Context API for auth state
- **Entry points**:
  - BE: `PetCareApplication.java` (Quarkus bootstrap) → REST controllers
  - FE: `main.jsx` → `App.jsx` (BrowserRouter + AuthProvider)
- **Key conventions**:
  - UUID-based IDs with prefix (user_, pet_, svc_, service_, notification_)
  - Portuguese for user-facing messages, English for code identifiers
  - JNoSQL annotations (@Entity, @Id, @Column) for MongoDB mapping
  - @RolesAllowed for endpoint authorization (tutor/owner)
  - CamelCase for Java, camelCase for JavaScript
